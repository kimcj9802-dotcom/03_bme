백엔드 만들기
FastAPI로 단일 파일 백엔드 app.py 를 만들어줘.
- 역할: 프론트가 보낸 {question, context} 를 받아, spark-2 AI 모델에 보내 답을 돌려준다.
- 모델 호출: POST http://121.138.151.6:11434/api/chat , 모델 "qwen3.6:35b-a3b" , stream:true
- 시스템 프롬프트: "참고 자료에만 근거해 한국어로 간결히 답한다. 자료에 없으면 '확인되지 않습니다'라고 한다."
- 엔드포인트: POST /api/chat (SSE 스트리밍으로 토큰 전송), GET /health
- CORS 허용, 포트 8000, httpx 사용.
- 중요: 프론트(HTML)가 ollama를 직접 호출하지 않고 반드시 이 백엔드를 거치게 설계할 것.


 프론트(화면) 만들기
단일 파일 index.html 프론트를 만들어줘.
- 구성: 질문 입력창 + 참고자료 입력칸 + 답변 영역 + 연결상태 표시등.
- 맨 위에 주소를 한 줄로 모아둘 것: const BE = "http://127.0.0.1:8000";  (이후 모든 호출은 BE + "/api/chat" 처럼 이 변수만 사용)
- 중요: 호출은 오직 내 백엔드(BE)로만 한다. ollama(11434) 직접 호출 절대 금지.
- (개인 과제에서 새 엔드포인트를 추가하더라도, 화면은 별도 안내가 없으면 공통 ①의 /api/chat(SSE)를 그대로 호출한다.)
- POST로 {question, context} 전송, SSE 응답을 실시간으로 답변 영역에 표시.
- 시작 시 GET BE + "/health" 로 연결 확인 후 상태 표시.
- 한국어 UI, 깔끔하게.


실행 (터미널)
pip install fastapi uvicorn httpx
# (먼저 포트가 비었는지 확인) — 아래가 응답하면 8000은 이미 사용중:curl -s http://127.0.0.1:8000/healthuvicorn app:app --port 8000          # ← 이 창은 켜둔 채로 둠(백엔드)
# 그 다음 index.html 을 더블클릭해 브라우저로 열기


내프로젝트는 "HTML 프론트 → FastAPI 백엔드(:8000) → ollama(:11434)" 구조다.
.claude/settings.json 에 넣을 훅을 JSON으로 만들어줘:
1) PreToolUse: HTML 파일에 "11434" 또는 "ollama" 직접 호출이 들어가면 차단하고 이유를 알려줄 것
2) PostToolUse: app.py(백엔드)가 수정되면 자동으로 점검 메시지 출력
3) Stop: 작업 끝나면 git status 를 보여줄 것 복붙 가능한 형식으로.


Playwright로 내 앱을 자동 테스트해줘.
1) 백엔드(:8000) 연결 확인
2) index.html 을 정적 서버 주소(http://127.0.0.1:5500)로 열기
※ file:// 로 직접 열면 fetch가 CORS로 막힌다. 같은 폴더에서 python -m http.server 5500 을 따로 켜고 그 주소로 연다.
3) 질문 입력칸에 "○○○(내 과제 질문)" 입력 후 전송
4) 답변이 뜨고(모델 응답이 늦을 수 있으니 최대 30초 대기), 출처가 표시되는지 확인
5) 통과/실패 리포트
테스트 코드(tests/qa.spec.ts)와 실행 방법도 같이 만들어줘.


프롬프트 1 — 매뉴얼 챗봇으로 맞추기 (기본)
공통 STEP 0 기본코드 챗봇(프론트(HTML) → 내 백엔드 http://127.0.0.1:8000 → 채팅 모델 qwen3.6:35b-a3b, POST http://121.138.151.6:11434/api/chat)을 '의료기기 수리 매뉴얼 챗봇'으로 맞춰줘.
- 모델 호출은 반드시 백엔드(app.py, :8000)에서만 한다. index.html/자바스크립트에서 121.138.151.6:11434·ollama를직접 호출하지 말 것(CORS·보안). 프론트는 오직 내 백엔드(:8000)만 부른다.
- 백엔드가 모델을 부를 때: POST http://121.138.151.6:11434/api/chat , 모델 "qwen3.6:35b-a3b".- index.html의 '참고자료' 칸 기본값(placeholder가 아니라 실제 채워진 값)으로 위 [DI-2200P 주입펌프 수리 매뉴얼 발췌 - 샘플] 8조각을 그대로 넣어줘.
- 백엔드 시스템 프롬프트를 이렇게 바꿔줘: "너는 의료기기 수리 매뉴얼 안내 도우미다.  참고 자료(매뉴얼 발췌)에만 근거해 한국어로 답한다.  증상을 물으면 '증상 → 점검 → 조치' 순서로 정리해 답한다.  자료에 없는 내용은 추측하지 말고 '매뉴얼에서 확인 불가'라고 답한다."
- 화면 제목을 "의료기기 수리 매뉴얼 챗봇 (DI-2200P)"으로.


프롬프트 2 — 근거(페이지·항목) 표시
답변할 때 어떤 매뉴얼 항목을 근거로 했는지 같이 보여줘.
- 답 마지막 줄에 "근거: <항목명> (p.OO)" 형식으로 출처를 표기
예) "근거: 폐색 알람(AL-OCC) p.42"
- 근거가 여러 개면 모두 나열.
- 자료에서 찾지 못하면 출처 줄 대신 "매뉴얼에서 확인 불가"로만 답해줘.
- (호출 경로는 그대로: 프론트(HTML)는 백엔드(:8000)만 부르고, 백엔드가 qwen3.6:35b-a3b를 POST http://121.138.151.6:11434/api/chat 로 호출한다. HTML에서 11434·ollama 직접 호출 금지.)


프롬프트 3 — 안전 고지 자동 추가
점검·조치를 안내하는 모든 답변 끝에, 아래 안전 고지를 자동으로 한 번덧붙여줘(매번 빠짐없이): "⚠ 본 안내는 자격 기술자 전용입니다. 임의 분해·내부 수리는 하지 마시고, 환자 연결 상태에서는 점검하지 마세요. 의심 시 제조사 서비스에 요청하세요."
- 단순 정보 조회(예: '센서 코드 종류 알려줘')에도 고지가 붙도록
- 사용자가 '분해하는 법 알려줘', '직접 고치는 법' 같은 걸 물으면, 절차 대신 "자격 기술자/제조사 서비스 대상"이라고 안내하고 분해방법은 알려주지 마.
- (시스템 프롬프트만 바꾸는 작업이라 호출 경로는 그대로: 백엔드(:8000) → qwen3.6:35b-a3b, POST http://121.138.151.6:11434/api/chat. HTML에서 11434·ollama 직접 호출 금지.)


프롬프트 4 — 자료 밖 질문 막기 (디버깅)
테스트해보니 매뉴얼에 없는 'DI-9999 모델 고장' 같은 질문에도 그럴듯하게 지어내서 답해. 이걸 고쳐줘.
- 참고 자료(매뉴얼 발췌)에 근거가 없으면, 절대 추측하지 말고 정확히이렇게만 답하게 해줘:"매뉴얼에서 확인 불가 — 해당 내용은 제공된 발췌에 없습니다. 정식매뉴얼/제조사 서비스를 확인하세요."
- 알람 코드(AL-OCC 등)나 오류 코드(E12 등)가 자료 목록에 없는 코드면, 그 코드는 "미수록 코드"라고 분명히 말하게 해줘.
- (백엔드 시스템 프롬프트 강화만 하는 작업. 호출은 그대로 백엔드(:8000) → qwen3.6:35b-a3b POST http://121.138.151.6:11434/api/chat. HTML 직접 호출 금지.


프롬프트 5 — Playwright 자동 점검 (검증)
Playwright로 내 매뉴얼 챗봇을 자동 테스트해줘.
- 호출 경로 전제: 프론트(HTML)는 백엔드(http://127.0.0.1:8000)만 부르고, 백엔드가 qwen3.6:35b-a3b를 POST http://121.138.151.6:11434/api/chat 로 호출한다(HTML에서 11434·ollama 직접 호출 금지).
1) 백엔드 http://127.0.0.1:8000/health 연결을 먼저 확인.
2) 브라우저로 index.html 열기.
3) 질문칸에 "폐색 알람 뜨면 어떻게 해?" 입력 후 전송.
4) 답변이 뜨고(35b 모델·스트리밍 첫 토큰 지연 감안: 타임아웃 15~20초로 넉넉히), 답에 "클램프" 또는 "라인"이 포함되는지 확인
5) 답 끝에 "자격 기술자" 안전 고지가 들어있는지 확인.
6) 셋 다 통과면 "통과", 하나라도 빠지면 "실패"로 리포트.
테스트 코드(tests/qa.spec.ts)와 실행 방법도 같이 만들어줘.


(여유 있으면) 리콜 대조도 ’챗봇’으로 — 코드가 계산, 챗봇이 답한다
백엔드 app.py에 POST /api/recall-check 를 추가하고, 그 결과를 매뉴얼 챗봇 답변창에서 자연어로 받게 해줘.
- 입력: 우리 보유 기기 표 + 리콜 공지 표(아래 샘플 형식 JSON 2개).
- 백엔드 파이썬 코드가 모델명+로트번호로 정확 매칭해 '리콜 대상'·'대상 아님'으로 분류하고, 대상 로트 목록과 건수(대상 N건/전체 M건)를 계산한다. 이 계산은 절대 모델에게 시키지 말 것(모델이 숫자를 세거나 매칭하면 안 됨 — 환각 방지). 파이썬이 만든 이 값이 '결정론적 정답값'이다.
- 그다음 그 정답값(대상 로트·건수)을 컨텍스트로 채팅 모델에 넘긴다: POST http://121.138.151.6:11434/api/chat , 모델 "qwen3.6:35b-a3b", 시스템 프롬프트 "아래 [리콜대조결과]에 적힌숫자와 로트만 인용해 한국어로 답하라. 결과에 없는 로트·건수를 지어내지 마라." 모델은 이 값을 인용해 한두 줄로만 답한다.
- index.html: 챗봇 답변창에 "리콜 대조 결과: 대상 1건(L2401), 대상 아님 1건(L2402). 
사유: 압력센서 결함." 처럼 자연어로 나오게 하고, 그 아래 출처 칩 "근거: /api/recallcheck 코드 계산값"을 단다. [리콜 대조] 버튼·결과 표는 보조로 남겨도 되지만 주가 아니다.
- 호출은 반드시 백엔드(http://127.0.0.1:8000/api/recall-check, /api/chat) 경유. 
HTML/자바스크립트에서 121.138.151.6:11434·ollama 직접 호출 금지.
- 원본은 수정하지 말고 결과만 반환.
