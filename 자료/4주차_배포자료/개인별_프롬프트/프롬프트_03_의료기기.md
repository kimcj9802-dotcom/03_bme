## 03. 의공팀 — 의료기기 · 공유 API 붙이기 프롬프트

> 대상: 의료기기 수리 매뉴얼 챗봇(주입펌프 DI-2200P) · RAG 근거검색 + 리콜 로트 대조 + 자격 고지
> 방식: 코드를 손으로 고치지 않습니다. 아래 프롬프트를 **Claude Code에 그대로 붙여넣어** AI에게 시킵니다.

---

### ① 한 줄 목표

내 챗봇이 **공유 게이트웨이(http://121.138.151.6:11500)** 를 쓰도록 주소 두 줄(채팅·임베딩)을 바꾸고, 이제 필요 없어진 think·num_predict 처리 코드를 정리하고, "자료에 없으면 확인되지 않습니다" 거절 규칙을 시스템 프롬프트에 확인·추가한다.

---

### ② 복붙 프롬프트 (이 블록을 그대로 Claude Code에 붙여넣기)

```text
너는 내 파이썬 프로젝트를 고쳐주는 개발 도우미야. 아래 작업을 순서대로 해줘.
이 앱은 의료기기(주입펌프 DI-2200P) 수리 매뉴얼 챗봇이고, RAG(근거검색)와 리콜 로트 대조 기능이 있어. 채팅과 임베딩을 둘 다 호출한다는 점이 중요해.

[1] 모델 주소를 공유 게이트웨이로 변경
- 본인 앱의 app.py 상단(대략 19~20행)에 있는 두 줄을 찾아줘:
    OLLAMA_URL = "...(채팅 주소)/api/chat"
    EMBED_URL  = "...(임베딩 주소)/api/embeddings"
- 두 줄의 호스트·포트를 모두 http://121.138.151.6:11500 으로 바꿔줘. 결과는 정확히 이렇게:
    OLLAMA_URL = "http://121.138.151.6:11500/api/chat"
    EMBED_URL  = "http://121.138.151.6:11500/api/embeddings"
- :11434 나 다른 주소로 남아 있는 곳이 파일 어디에도 없는지 전체를 한 번 더 확인해줘. 채팅과 임베딩 둘 다 :11500 이어야 해.
- 바로 아래에 있는 모델명 변수(MODEL, EMBED_MODEL 등, 예: qwen3.6, bge-m3)는 게이트웨이가 알아서 정규화하니까 절대 건드리지 마.

[2] 이제 필요 없어진 think / num_predict 처리 코드 정리
- 게이트웨이가 think:false 와 num_predict 상한을 자동으로 처리해줘. 그래서 앱 쪽에서 그걸 직접 다루던 코드는 더 이상 필요 없어.
- 채팅·임베딩을 호출하는 요청 payload(보통 requests.post(...)의 json=... 부분)에서 다음을 찾아 정리해줘:
    · "think": true/false 옵션을 보내는 부분 → 제거
    · options 안의 "num_predict" 로 길이를 강제로 제한하던 부분 → 제거
    · 응답에서 <think> ... </think> 같은 모델 혼잣말(추론 텍스트)을 잘라내려고 만든 후처리 코드가 있으면 → 제거 (게이트웨이가 이미 걸러줌)
- 확실치 않으면 지우기 전에 "이 줄을 지워도 되는지" 나한테 먼저 물어봐. 관련 코드가 원래 없었다면 "없음"이라고만 알려줘.

[3] 거절 규칙(안전 고지)을 시스템 프롬프트에 확인·추가
- 본인 앱의 시스템 프롬프트(모델에게 역할을 지시하는 문자열, 보통 SYSTEM_PROMPT 나 messages의 role:"system" 부분)를 찾아줘.
- 거기에 아래 규칙이 이미 있는지 확인하고, 없으면 자연스럽게 추가해줘(한국어로):
    · "제공된 매뉴얼·자료(검색된 근거)에 없는 내용은 지어내지 말고 '자료에 없어 확인되지 않습니다'라고 답한다."
    · "이 답변은 자료 안내용이며 시술·수리 지시가 아니다. 실제 분해·내부 수리는 자격 기술자/제조사 서비스 대상임을 답변 끝에 고지한다."
    · "환자정보·실제 시리얼/로트 번호는 다루지 않는다."
- 원래 있던 출처 표기(근거: ... p.OO)와 자격 고지 문구는 그대로 유지해줘. 새 규칙과 충돌하지 않게.

[4] 마무리
- 위에서 바꾼 파일과 줄을 요약해서 보여주고, 문법 오류가 없는지 확인해줘.
- 실행 방법(백엔드 uvicorn, 프론트 http.server)은 바꾸지 말고 그대로 둬.
```

---

### ③ 이 프롬프트가 실제로 바꾸는 것

- **주소 두 줄**: 채팅(OLLAMA_URL)·임베딩(EMBED_URL)이 모두 공유 게이트웨이 :11500 을 가리키게 됩니다. (이 앱은 임베딩도 쓰므로 한 줄이 아니라 두 줄입니다.)
- **군더더기 정리**: think 옵션·num_predict 길이 제한·`<think>` 잘라내기 후처리가 사라집니다. 게이트웨이가 대신 처리하므로 코드가 단순해집니다.
- **거절 규칙 명시**: 검색된 자료에 없으면 "확인되지 않습니다"라고 답하고, 자격 고지를 붙이는 규칙이 시스템 프롬프트에 확실히 들어갑니다.
- **안 바뀌는 것**: 모델명(qwen3.6, bge-m3)과 실행 방식은 그대로입니다.

---

### ④ 붙인 뒤 확인

1. **게이트웨이 살아있나** — 터미널에서:
   ```bash
   curl http://121.138.151.6:11500/health
   ```
   정상 응답이 오면 게이트웨이 준비 완료입니다.

2. **앱 기동** — 터미널 2개(본인 앱 폴더에서):
   ```bash
   python -m uvicorn app:app --port 8000      # 터미널 1 (백엔드)
   python -m http.server 5500                 # 터미널 2 (프론트)
   ```
   브라우저에서 `http://127.0.0.1:5500/index.html` 접속 → 상단 연결 상태가 초록이면 정상.

3. **대표질문 1개** — 채팅창에 입력:
   ```
   E15 오류가 뜨는데 어떻게 하나요?
   ```
   기대: "E15 압력센서 신호 불안정 → 캘리브레이션 필요(자격 기술자 전용)" 취지 안내 + 출처 칩(근거: ... p.78) + 자격 고지 한 줄. 답변에 `<think>` 같은 혼잣말이 안 보이면 성공입니다.

---

### ⑤ 안전

- **더미·비식별 값만 사용**: 질문·리콜 대조 입력에 환자 이름·환자번호·실제 시리얼/로트를 넣지 마세요. 실습은 더미 로트(예: L2401, L2402)만.
- **안내용이지 수리 지시 아님**: 챗봇은 자료에 있는 내용만 안내합니다. 실제 분해·내부 수리는 자격 기술자/제조사 서비스 대상입니다. 답변 끝 자격 고지를 반드시 함께 읽으세요.
- **거절 규칙 확인**: 자료에 없는 내용을 지어내지 않고 "확인되지 않습니다"라고 답하는지 위 ②[3] 규칙이 시스템 프롬프트에 들어갔는지 꼭 확인하세요.
- **공유 GPU 1개**: 모두가 GPU 하나를 같이 씁니다. 답이 끝난 뒤 다음 질문을 보내세요(긴 질문 연달아 금지).
