## 05. 약제부 — hira비급여조회 · 공유 API 붙이기 프롬프트

### ① 한 줄 목표
내 비급여조회 앱의 챗봇을 **공유 게이트웨이(:11500)** 에 붙이고, 게이트웨이가 대신 처리해 주는 불필요한 코드를 정리하며, "자료에 없으면 답하지 않는" 거절 규칙을 시스템 프롬프트에 넣는다. (손으로 고치지 말고 아래 프롬프트를 Claude Code에 그대로 붙여넣는다.)

---

### ② 복붙 프롬프트 (Claude Code에 그대로 붙여넣기)

```text
너는 내 파이썬 Flask 앱(hira 비급여조회 챗봇)을 수정하는 코딩 도우미야.
앱은 app.py 단일 파일 + templates/index.html 로 되어 있고,
챗봇은 브라우저가 아니라 백엔드(Flask)가 모델 서버로 대신 호출(프록시)하는 구조야.
아래 4가지를 순서대로, 최소 변경으로만 처리해줘. 각 단계마다 무엇을 바꿨는지 한 줄로 알려줘.

1) 모델 주소를 공유 게이트웨이로 고정
   - 본인 앱의 모델 주소 변수(OLLAMA_URL, app.py 상단)를 찾아줘.
   - 값이 "http://121.138.151.6:11500" 이면 그대로 두고 "이미 게이트웨이로 설정됨"이라고만 알려줘.
   - 만약 포트가 11434 등 다른 값이면 IP(121.138.151.6)는 그대로 두고 포트만 11500으로 바꿔줘.
   - 챗봇 호출부와 모델목록 조회부가 이 변수를 그대로 쓰는지도 확인해줘.

2) 모델명은 건드리지 마
   - 채팅 모델명 변수(CHAT_MODEL, 예: "qwen2.5:14b-instruct-q4_K_M")는 절대 바꾸지 마.
   - 게이트웨이가 모델명을 알아서 보정해 주니 그대로 두면 돼.

3) 게이트웨이가 대신 처리하므로 불필요해진 코드 정리
   - 게이트웨이(:11500)가 추론 누출 차단(think:false 강제)과 답변 길이 상한을 서버에서 처리해줘.
   - 그러니 본인 앱이 모델 호출 payload에 직접 넣던 다음 것들은 정리해도 돼:
     · options 안의 num_predict(답변 길이 상한) 같은 값
     · think 관련 옵션이나, 응답에서 <think>...</think>를 잘라내려고 직접 만든 후처리 코드
   - 다만 이건 "있으면 정리, 없으면 그냥 둔다" 수준으로만. 있는지 먼저 보여주고, 지워도 앱이 동작하는지 확인한 뒤 지워줘.
   - 스트리밍 여부(stream)나 타임아웃 등 동작에 필요한 옵션은 건드리지 마.

4) 거절 규칙을 시스템 프롬프트에 확인·추가
   - 챗봇에 넘기는 시스템 프롬프트(안내 역할 지시문)를 찾아줘.
   - 아래 취지의 규칙이 이미 있는지 확인하고, 없으면 자연스럽게 추가해줘:
     "제공된 비급여 데이터/검색 결과에 없는 내용은 지어내지 말고
      '자료에 없어 확인되지 않습니다'라고 답한다. 특정 병원의 정확한 금액을
      단정하지 말고, 필요하면 답변에 [SEARCH:키워드] 형식으로 검색 버튼을 넣어 안내한다."
   - 기존 [SEARCH:키워드] 규칙(답변에 검색 버튼을 넣는 기능)은 그대로 유지해줘.

작업 후: 바뀐 줄만 diff로 요약하고, 앱을 실행하는 방법(포트 포함)을 한 줄로 알려줘.
```

---

### ③ 이 프롬프트가 실제로 바꾸는 것
- **모델 주소**를 공유 게이트웨이 `:11500`으로 고정한다 (이미 되어 있으면 확인만).
- 모델 호출에서 직접 넣던 **`num_predict`(길이 상한)·`<think>` 후처리** 등 게이트웨이가 대신 하는 코드를 정리한다.
- 시스템 프롬프트에 **"자료에 없으면 확인되지 않습니다" 거절 규칙**을 넣는다 (환자·금액 지어내기 방지).
- **모델명(`qwen2.5:14b...`)과 `[SEARCH:키워드]` 기능은 그대로** 둔다 — 게이트웨이가 모델명을 보정해 준다.

---

### ④ 붙인 뒤 확인
```bash
# 1) 게이트웨이가 살아있나
curl http://121.138.151.6:11500/health

# 2) 앱 기동 (run.sh가 .env를 읽고 python3 app.py 실행)
cd hira-app/hira-app
./run.sh
```
- **접속 포트는 8080**이다. `run.sh`는 5000이라고 안내하지만 실제 기본값은 `http://localhost:8080`. (5000을 쓰려면 `PORT=5000 ./run.sh`)
- **대표 질문 1개**를 챗봇에 넣어본다: **"창원에서 무릎 인공관절 수술 비급여 가격이 궁금해요"**
  - 기대: 3~5문장으로 간결히 답하고, 답변 안에 `[SEARCH:인공관절]` 같은 검색 버튼이 생긴다.
  - 답변에 `<think> … </think>` 같은 생각 과정이 보이거나 답이 비어 있으면, 주소가 `:11434`로 돌아간 것 → ①을 다시 확인.

### ⑤ 안전
- **더미·비식별만.** 챗봇 입력창에 환자 이름·등록번호·진단명 같은 개인정보는 절대 넣지 않는다. 질문은 "OO 수술 비급여 가격대"처럼 **항목 단위**로만.
- **거절 규칙 유지.** 자료(검색 결과)에 없는 금액을 단정하지 말고 "확인되지 않습니다"로 답하게 둔다.
- **데이터·키 반출 금지.** `MOCK_DATA`·`cache.pkl`(공공데이터)과 `.env`의 심평원 API 키를 외부(메신저·메일)로 보내지 않는다.
- **공유 GPU는 1대.** 여러 명이 동시에 첫 기동/긴 질문을 몰지 말고 순서대로. 느려도 잠시 기다린다.
