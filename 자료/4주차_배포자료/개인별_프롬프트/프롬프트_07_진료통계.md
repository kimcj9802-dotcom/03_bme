## 07. 기획·통계 — 진료통계 · 공유 API 붙이기 프롬프트

### ① 한 줄 목표
내 진료통계 챗봇(app.py)의 모델 주소 두 곳을 공유 게이트웨이(`:11500`)로 바꾸고, 없는 진료과는 "확인되지 않습니다"로 거절하도록 AI에게 시켜서 붙인다.

---

### ② 복붙 프롬프트 (Claude Code 창에 그대로 붙여넣기)

```text
너는 내 진료통계 RAG 챗봇의 백엔드(app.py, FastAPI)를 수정하는 조수야.
직접 손으로 안 고치고 너에게 시킨다. 아래를 순서대로 정확히 해줘.

[전제]
- 공유 게이트웨이 주소는 http://121.138.151.6:11500 이다.
- 이 게이트웨이가 think(추론 누출) 끄기, 출력 길이 상한(num_predict),
  모델명 정규화를 자동으로 해준다. 그러니 그 처리를 앱 코드에 넣지 마라.

[1] 모델 주소 두 곳을 모두 :11500 으로 맞춰라 (중요: 한 곳만 바꾸면 안 됨)
- 본인 앱의 app.py 안에서 모델 주소가 박힌 곳이 두 군데다.
  (기준 주소 OLLAMA_BASE 한 곳, /health 안에서 /api/tags 를 조회하는 한 곳)
- 두 곳 모두 http://121.138.151.6:11500 을 가리키는지 확인하고,
  :11434 등 다른 포트가 남아 있으면 :11500 으로 바꿔라.
- 한 곳만 바꾸면 답변은 새 주소로 가지만 /health 상태등은 옛 주소를 봐서
  꼬인다. 그래서 반드시 두 곳 다 확인해라.
- 더 낫게: /health 쪽은 하드코딩 대신 이미 있는 OLLAMA_BASE 변수를
  재사용하도록 f"{OLLAMA_BASE}/api/tags" 형태로 바꿔라. 그래야 한 곳만
  고쳐도 두 곳이 같이 움직인다.

[2] 이제 게이트웨이가 대신 해주니, 불필요해진 처리를 정리해라
- 본인 앱 코드 어딘가에 think 를 끄는 옵션, <think>...</think> 를 지우는
  후처리, num_predict(출력 길이) 를 직접 세팅하는 코드가 있으면 게이트웨이와
  중복이다. 있으면 제거하거나 주석으로 설명을 달아라. 없으면 "없음"이라고만
  알려주고 새로 추가하지 마라.

[3] "자료에 없으면 확인되지 않습니다" 거절 규칙을 확인·강화해라
- 이 앱은 근거줄(DOCS)만 인용해서 답하도록 되어 있다. 시스템 프롬프트에
  "근거(컨텍스트)가 비어 있으면 반드시 '확인되지 않습니다'라고만 답하고,
   숫자를 지어내지 말라"는 규칙이 들어 있는지 확인하고, 없으면 추가해라.
- 추가로 진료과 화이트리스트 거절을 넣어라: 근거 데이터에 실제로 존재하는
  진료과 목록(예: 소화기내과·순환기내과·외과·정형외과·신경외과 등, 본인 앱의
  DOCS에서 실제 등장하는 진료과로 목록을 만들어라)을 코드 상수로 두고,
  질문에 들어온 진료과가 그 목록에 없으면 모델을 호출하기 전에 곧바로
  "확인되지 않습니다"를 반환해라.
  (예: "안과 외래 건수는?" 처럼 데이터에 없는 진료과 질문은 가까운 다른
   진료과 수치를 끌어다 답하면 안 되고, 무조건 거절해야 한다.)

[4] 마지막으로 바뀐 부분을 요약해서 알려줘
- 어느 파일 몇 번째 줄을 어떻게 바꿨는지, 거절 규칙을 어디에 넣었는지
  3~5줄로 정리해줘. 코드가 문법적으로 정상인지도 확인해줘.
```

---

### ③ 이 프롬프트가 실제로 바꾸는 것 (3~4줄)
- app.py의 모델 주소 **두 곳(약 22행 · 277행)** 을 모두 게이트웨이 `:11500`으로 맞추고, `/health`는 `OLLAMA_BASE` 변수를 재사용하도록 정리한다.
- 게이트웨이가 대신 처리하는 **think 끄기 · num_predict 상한 · 모델명 정규화** 관련 중복 코드를 정리한다(있을 때만).
- 시스템 프롬프트에 **"근거 없으면 확인되지 않습니다"** 거절 규칙을 확인·추가한다.
- **진료과 화이트리스트**를 두어, 데이터에 없는 진료과 질문은 모델 호출 전에 곧바로 거절한다(안과 등 숫자 환각 차단).

---

### ④ 붙인 뒤 확인
1. 게이트웨이 살아 있는지: 터미널에서
   ```bash
   curl http://121.138.151.6:11500/health
   ```
2. 내 앱(백엔드) 기동: `app.py` 폴더에서
   ```bash
   uvicorn app:app --host 0.0.0.0 --port 8000 --reload
   ```
   그리고 상태등 확인: `curl http://127.0.0.1:8000/health` → `"status":"ok"` 나오면 정상.
3. 대표질문 1개 (있는 진료과 → 정상 집계):
   ```bash
   curl -X POST http://127.0.0.1:8000/api/aggchat \
     -H "Content-Type: application/json" \
     -d '{"question":"소화기내과 외래 건수는?","bare":false}'
   ```
   → 기대 답 **84** (근거줄 "소화기내과 외래 합계 84" 인용).
4. 거절 확인 (없는 진료과 → 거절):
   ```bash
   curl -X POST http://127.0.0.1:8000/api/aggchat \
     -H "Content-Type: application/json" \
     -d '{"question":"안과 외래 건수는?","bare":false}'
   ```
   → 기대 답 **"확인되지 않습니다"** (엉뚱한 일별 수치를 끌어오면 실패).
   - 답변에 `<think>` 나 "사용자가 묻는 것은…" 같은 혼잣말이 섞이면 주소가 옛 포트로 남은 것 → ③번 두 곳을 다시 확인.

### ⑤ 안전
- **더미·비식별만**: 근거 데이터(DOCS)는 실제 병원 운영수치로 추정되므로, 실습·시연 때는 **가짜 숫자**로 바꿔 쓰고 실값을 외부로 캡처·공유하지 않는다.
- **환자정보 입력 금지**: 질문창에 환자 이름·차트번호·진단명 등 식별정보를 넣지 않는다. 건수·합계·최다/최소 같은 통계 질문만 다룬다.
- **거절 규칙이 핵심**: "정확히 답하기"보다 **"모를 때 거절하기"** 를 코드로 박는 것이 품질을 가른다. 없는 진료과·근거 없는 질문은 반드시 "확인되지 않습니다"로 막는다.
- **동시성 주의**: 공유 GPU 한 대를 함께 쓰므로 비교 기능은 한 질문을 두 번 호출한다. 여러 명이 동시에 누르면 느려지니 한 명씩 천천히 시연한다.
