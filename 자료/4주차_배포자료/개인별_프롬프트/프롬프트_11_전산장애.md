## 11. 정보지원팀 — 전산장애 · 공유 API 붙이기 프롬프트

### 1) 한 줄 목표

내 전산장애 안내 챗봇(근거기반 RAG)이 각자 띄우던 모델 주소 대신 **공유 게이트웨이(`:11500`)** 를 쓰도록 바꾸고, 자료에 없는 질문은 "확인되지 않습니다"로 거절하게 만든다.

---

### 2) 복붙 프롬프트 (Claude Code에 그대로 붙여넣기)

> 아래 회색 박스를 통째로 복사해서 Claude Code 입력창에 붙여넣으세요. 손으로 코드를 고치지 않습니다 — AI에게 시킵니다.

```
너는 내 코드를 고쳐 주는 도우미야. 아래 작업을 순서대로 해줘.

[배경]
- 내 앱은 정보지원팀 전산장애/업무 안내용 근거기반(RAG) 챗봇이야.
  프론트(HTML 화면)는 내 백엔드만 호출하고, 모델(임베딩·채팅) 호출은 백엔드가 해.
- 지금까지는 각자 띄운 모델 서버(11434 포트)를 썼는데,
  이제 공유 게이트웨이 http://121.138.151.6:11500 으로 바꿔야 해.
- 게이트웨이가 think:false(생각 누출 차단), 응답 길이 상한,
  모델명 정규화를 자동으로 처리해줘. 그래서 그 처리 코드는 이제 필요 없어.

[작업 1] 모델 주소를 게이트웨이로 변경
- 본인 앱의 백엔드 코드에서 모델 서버 주소가 들어간 줄을 모두 찾아줘.
  (예: OLLAMA_URL 같은 변수, 또는 http://...:11434, localhost:11434, 127.0.0.1:11434)
- 그 주소를 전부 http://121.138.151.6:11500 로 바꿔줘.
- 임베딩(검색)·생존확인(tags)·채팅 세 가지 호출이 모두 이 주소를 쓰는지 확인해줘.
- 주소를 바꿀 곳이 한 군데뿐이 되도록, 주소는 코드 상단의 변수 한 곳에
  모아 두고 나머지는 그 변수를 참조하게 정리해줘.

[작업 2] 이제 불필요해진 코드 정리
- 요청 본문(payload)에 think 값을 직접 넣거나 <think> 태그를 잘라내는 처리가 있으면
  게이트웨이가 대신 해주니 지워도 되는지 알려주고, 안전하면 정리해줘.
- 응답 길이 상한(num_predict / max_tokens 등)을 코드에서 강제로 넣던 부분이 있으면
  게이트웨이가 상한을 걸어주니 제거하거나 주석으로 남겨줘.
- 모델 이름을 특정 형태로 바꿔치기하던 코드가 있으면, 게이트웨이가 정규화하니
  단순하게 정리해줘.
- 단, 확신이 안 서는 부분은 지우지 말고 나한테 먼저 물어봐줘.

[작업 3] 거절 규칙을 시스템 프롬프트에 확인·추가
- 본인 앱의 시스템 프롬프트(모델에게 주는 지시문/역할 문구)를 찾아줘.
- 아래 규칙이 이미 있으면 그대로 두고, 없으면 추가해줘:
  "제공된 자료(검색된 근거 조각)에 없는 내용은 지어내지 말고
   '확인되지 않습니다'라고 답한다. 서버 비밀번호·관리자 계정·상세 IP 대역 같은
   보안정보나 환자 개인정보를 묻는 질문에는 모델을 부르지 말고
   '보안상 안내하지 않습니다'로 답한다.
   답변에는 근거가 된 출처 태그를 함께 표시한다."

[작업 4] 요약
- 무엇을 어디서(파일명·줄 위치) 바꿨는지 3~4줄로 알려줘.
- 내가 직접 확인해볼 방법(curl, 앱 실행)도 한 줄로 알려줘.
```

---

### 3) 이 프롬프트가 실제로 바꾸는 것

- 본인 앱의 모델 주소 줄(11434 → `121.138.151.6:11500`)을 전부 게이트웨이로 교체합니다.
- `think` 처리·응답 길이 상한·모델명 변환 등 게이트웨이가 대신 해주는 코드를 정리합니다.
- 시스템 프롬프트에 "자료에 없으면 확인되지 않습니다" + "보안정보는 안내하지 않습니다" 거절 규칙을 확인·추가합니다.
- 결과적으로 생각(혼잣말) 누출이 사라지고, 여러 명이 몰려도 빈 답 없이 안정적으로 동작합니다.

---

### 4) 붙인 뒤 확인

**(1) 게이트웨이 생존 확인**
```bash
curl http://121.138.151.6:11500/health
```
정상 응답이 오면 공유 서버가 살아 있는 것입니다.

**(2) 내 앱 기동 후 백엔드 확인**
```bash
uvicorn app:app --port 8000
curl http://127.0.0.1:8000/health
# 예: {"ok":true,"ollama":true,...}  → "ollama":true 면 게이트웨이까지 연결 정상
```
그다음 프론트를 띄웁니다. `index.html`을 더블클릭하면 CORS로 막힐 수 있으니, 같은 폴더에서 `python -m http.server 5500` 실행 후 브라우저에서 `http://127.0.0.1:5500/index.html` 을 여세요.

**(3) 대표 질문 1개**

화면 입력창에 아래를 넣어 봅니다.
```
CD 분석이 안 돼요
```
기대 동작: 출처 태그(예: 📎 외부영상CD-CD분석중)와 함께 "CD-ROM 교체, 담당은 정보지원팀" 같은 근거 답이 나오고, `<think>` 같은 혼잣말이 섞이지 않습니다. 자료에 없는 질문에는 "확인되지 않습니다"가 나오면 성공입니다.

---

### 5) 안전 수칙

- **더미·비식별 데이터만** — 자료 조각과 테스트 질문은 모두 연습용·비식별만 사용합니다. 실제 사례·내부 통계·담당자 실명/연락처는 넣지 않습니다.
- **환자 개인정보·보안정보 금지** — 환자명·등록번호는 물론 서버 비밀번호·관리자 계정·상세 IP 대역도 입력 금지. 이런 질문에는 모델을 부르지 말고 "보안상 안내하지 않습니다"로 차단합니다.
- **거절 규칙 유지** — 자료(검색 근거)에 없는 내용은 지어내지 말고 "확인되지 않습니다"로 답하게 합니다.
- **분리 강제** — 화면(`index.html`)에서 모델을 직접 부르지 말고, 모델 호출은 오직 백엔드(`:8000`) 경유로.
- **공유 서버 예절** — 게이트웨이 뒤 GPU는 모두가 함께 씁니다. 한 번에 한 질문씩, 테스트가 끝나면 `uvicorn`을 내리세요(Ctrl+C). 모델 서버 주소(`:11500`)는 외부 공유 금지.
