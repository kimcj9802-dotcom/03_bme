## 04. 인사 — 휴가안내 · 공유 API 붙이기 프롬프트

### ① 한 줄 목표
내 휴가안내 챗봇(규정 검색형)이 공유 게이트웨이(`http://121.138.151.6:11500`)를 바라보게 바꾸고, 불필요해진 처리 코드를 정리하고, "규정에 없으면 확인 불가" 거절 규칙을 확실히 켠다.

---

### ② 복붙 프롬프트 (Claude Code에 그대로 붙여넣기)

아래 블록을 통째로 복사해서 Claude Code 입력창에 붙여넣으세요. (손으로 코드를 고치지 않습니다. AI가 대신 고칩니다.)

```
내 휴가안내 챗봇(사내 휴가 규정을 조각으로 검색해서 그 근거로만 답하는 RAG 앱)을 공유 게이트웨이에 붙이려고 해. 아래를 순서대로 해줘.

1) 모델 서버 주소 바꾸기
   - 본인 앱 백엔드에서 모델 서버 주소를 담은 줄(보통 OLLAMA_URL 같은 변수, 또는 CHAT_URL / EMBED_URL 처럼 채팅용·임베딩용 두 줄)을 모두 찾아줘.
   - 그 주소의 포트를 전부 11500 으로 바꿔줘. 즉 http://121.138.151.6:11500 을 가리키게 해줘.
   - IP(121.138.151.6)와 경로(/api/chat, /api/embeddings)는 그대로 두고, 포트 숫자만 11500으로 통일해줘.
   - 이 앱은 검색(임베딩)과 답변(채팅) 두 종류 호출을 쓰니까, 두 호출 주소가 둘 다 11500을 가리키는지 반드시 확인해줘. 한쪽만 바뀌면 안 돼.
   - 가능하면 주소를 환경변수로 뺄 수 있게 해줘: os.environ.get("OLLAMA_URL", "http://121.138.151.6:11500") 형태. 단 기존 동작이 깨지면 그냥 값만 바꿔줘.

2) 불필요해진 처리 코드 정리
   - 게이트웨이가 생각 끄기(think:false)와 답변 길이 상한(num_predict)과 모델명 보정을 자동으로 처리해줘. 그러니 본인 앱에 남아 있는 관련 코드를 정리해줘.
   - 모델 호출 요청 본문(payload/json)에 think 관련 옵션이나 num_predict(또는 max_tokens 성격의 상한)를 직접 넣는 부분이 있으면 제거하거나 주석 처리해줘.
   - 응답에서 <think>...</think> 같은 사고 과정 텍스트를 잘라내던 후처리 코드가 있으면, 이제 게이트웨이가 걸러주니 지워도 되는지 알려주고 정리해줘.
   - 모델명(qwen3.6:35b-a3b 같은 채팅 모델, bge-m3:latest 같은 임베딩 모델)은 손대지 마. 게이트웨이가 알아서 실제 모델로 연결해줘.
   - 삭제·수정한 부분을 나한테 짧게 요약해줘.

3) 거절 규칙(안전장치) 확인·보강
   - 시스템 프롬프트(또는 답변 생성 지침)에 "검색된 규정 조각에 근거가 없으면 지어내지 말고 '확인되지 않습니다 — 인사팀에 문의하세요'로 답하라"는 규칙이 있는지 확인해줘.
   - 없으면 추가하고, 약하면 더 분명하게 고쳐줘.
   - 개인 휴가내역·잔여일수 질문("내 연차 며칠 남았어?")에는 "개인 휴가내역은 이 챗봇에서 확인할 수 없습니다"로 답하도록 규칙도 넣어줘.
   - 규정에 없는 일수·조건·금액을 추측해서 답하지 않도록 못 박아줘.

바꾼 파일과 바뀐 줄을 요약해서 알려주고, 실행해서 확인하는 방법도 알려줘.
```

---

### ③ 이 프롬프트가 실제로 바꾸는 것
- 모델 주소의 포트를 `:11434`(각자 직접 띄우던 raw) → `:11500`(공유 게이트웨이)으로 통일합니다. 채팅·임베딩 두 호출 모두.
- 앱 안에 남아 있던 `think` 옵션·`num_predict` 상한·`<think>` 잘라내기 후처리를 정리합니다. 이제 게이트웨이가 대신 처리하기 때문입니다.
- 모델명은 그대로 둡니다. 게이트웨이가 공유 서버의 실제 모델로 자동 보정합니다.
- 시스템 프롬프트의 "근거 없으면 확인 불가" 거절 규칙을 확인·보강합니다.

---

### ④ 붙인 뒤 확인 (순서대로)
1. 게이트웨이가 살아 있는지 먼저 확인
   ```bash
   curl http://121.138.151.6:11500/health
   ```
   `ok`(또는 짧은 상태 JSON)가 나오면 정상입니다. 응답이 없으면 강사에게 알리세요.
2. 내 앱 기동 (앱 폴더 안에서)
   ```bash
   python -m uvicorn app:app --port 8000
   ```
   처음 질문 때 임베딩 캐시 로그(예: `8개 청크 캐시 완료`)가 뜨면 검색이 게이트웨이로 잘 붙은 것입니다.
3. 대표 질문 1개로 끝까지 확인 — 챗봇 입력창에 한 줄:
   > **"병가 진단서 필요해?"**

   기대: `[병가]` 조각을 근거로 "연속 3일 이상 사용 시 의사 진단서 제출" 같은 답이 나오고, 답 아래 작은 회색 글씨로 `출처: [병가]`가 붙습니다. 답 안에 `<think> … </think>` 같은 사고 과정 텍스트가 보이면 주소가 아직 `:11434`로 남은 것이니 ②를 다시 확인하세요.

### ⑤ 안전
- **더미·비식별만.** 테스트는 강의용 휴가 규정 더미 8조각으로만 합니다. 실제 사내 규정, 직원 이름·사번·진단명은 챗봇·코드에 절대 넣지 마세요.
- **개인 휴가내역 금지.** 이 앱은 규정 안내 전용입니다. "내 연차 며칠 남았어?" 같은 개인 사용내역은 답하지 않는 게 정상입니다.
- **거절 규칙 필수.** 규정에 없으면 지어내지 말고 "확인되지 않습니다 — 인사팀에 문의하세요"로 막혀야 합니다. 지어낸 일수·조건은 인사 사고로 이어집니다.
- **공유 GPU는 1대.** 여러 명이 함께 씁니다. 답이 다 나온 뒤 다음 질문을 보내고, 느리면 잠시 기다리세요.
