## 09. 감염관리실 — 감염관리 · 공유 API 붙이기 프롬프트

> 손으로 코드를 고치지 않습니다. 아래 **복붙 프롬프트**를 Claude Code(AI 코딩 도구)에 그대로 붙여넣고, AI가 바꾸게 시키세요.

---

### ① 한 줄 목표

내 감염관리 챗봇(제출 앱)이 각자 띄우던 raw 주소 대신 **공유 게이트웨이(`http://121.138.151.6:11500`)** 로 붙어서, think 누출 없이 출처와 함께 답하고 자료에 없으면 "확인되지 않습니다"로 거절하게 만든다.

---

### ② 복붙 프롬프트 (이걸 Claude Code에 그대로 붙여넣기)

```
너는 내 감염관리 임상지원 챗봇(FastAPI + RAG) 코드를 고치는 페어 프로그래머야.
아래 4가지만 정확히 수행하고, 그 외 로직(RAG 검색, 출처 태그, PHI 차단, CALC 힌트)은 절대 건드리지 마.

[대상 파일] 본인 앱의 app.py (FastAPI 백엔드). 필요하면 먼저 열어서 현재 상태를 확인하고 시작해.

1) 모델 주소를 공유 게이트웨이로 고정
   - app.py 상단의 모델 서버 상수(OLLAMA = "http://...")가
     반드시 "http://121.138.151.6:11500" 을 가리키게 해줘.
   - 혹시 아직 ":11434"(각자 띄우던 raw 주소)로 되어 있으면 ":11500"으로 바꿔줘.
   - 이 상수 하나가 임베딩 호출(/api/embeddings), 생존 확인(/api/tags),
     채팅 스트리밍(/api/chat) 세 곳에서 모두 쓰이는지 확인하고,
     세 곳 다 이 게이트웨이 주소를 경유하는지 점검해줘.
   - 임베딩 모델(bge-m3)도 반드시 이 게이트웨이를 거쳐 호출되어야 해.
     별도의 다른 주소로 임베딩만 따로 부르는 코드가 있으면 게이트웨이로 통일해줘.

2) 게이트웨이가 대신 처리하므로 불필요해진 방어 코드 정리
   - 게이트웨이가 think:false(모델 혼잣말 끄기)와 num_predict 상한을 자동으로 걸어줘.
   - 그러니 모델 호출 payload에서 내가 직접 넣던 "think" 값이나 "num_predict"
     같은 옵션을 직접 지정하는 부분이 있으면 제거해줘(게이트웨이가 처리).
   - 응답에서 "<think>...</think>" 태그를 지우는 정규식이 있으면,
     이제는 게이트웨이가 추론 자체를 끄므로 사실상 필요 없어.
     스트림 안전용 보조로 아주 짧게 한 줄만 남기거나, 없어도 되면 지워서 코드를 깔끔히 해줘.
     (지우든 남기든 하나만 골라서 정리하고, 왜 그렇게 했는지 한 줄로 설명해줘.)

3) 거절 규칙을 시스템 프롬프트에서 확인·보강
   - 이 앱은 사내 감염관리 지침 조각(IC-01~IC-08)을 검색해 출처와 함께 답하는 RAG 챗봇이야.
   - 백엔드의 시스템 프롬프트에 "검색된 지침 자료에 근거가 없으면 지어내지 말고
     '확인되지 않습니다'라고 답하라"는 규칙이 있는지 확인해줘.
   - 없으면 추가하고, 있으면 문구를 명확히 다듬어줘.
     핵심: 근거 없는 추측·창작 금지, 자료에 없으면 확인되지 않는다고 명시.

4) 환자 식별정보(PHI) 차단은 그대로 유지
   - 환자명·등록번호·주민번호·"병실+이름" 같은 식별정보가 들어오면
     모델 호출 없이 즉시 차단하는 기존 로직은 절대 지우거나 약화시키지 마. 그대로 둬.

[마무리]
- 위 변경으로 깨진 import나 문법 오류가 없는지 확인해줘.
- 무엇을 어디(줄 번호/함수)에서 어떻게 바꿨는지 한국어로 3~5줄 요약해줘.
- 확실하지 않으면 임의로 고치지 말고 나에게 먼저 물어봐.
```

---

### ③ 이 프롬프트가 실제로 바꾸는 것

- 모델 서버 주소를 `:11500`(게이트웨이)로 고정 — 임베딩 · 생존확인 · 채팅 **세 호출**이 한 상수로 전부 게이트웨이를 경유합니다.
- 내가 직접 넣던 `think` · `num_predict` 옵션과 `<think>` 제거 정규식을 정리 — 이제 게이트웨이가 대신 막아줘서 코드가 가벼워집니다.
- 시스템 프롬프트에 "자료에 없으면 확인되지 않습니다" 거절 규칙을 확인·보강 — RAG 근거 없는 헛답을 막습니다.
- PHI 차단은 손대지 않고 그대로 유지 — 안전장치는 약화되지 않습니다.

---

### ④ 붙인 뒤 확인 (순서대로)

1. 게이트웨이가 살아있나
   ```bash
   curl http://121.138.151.6:11500/health
   ```
   정상 응답이 오면 게이트웨이 OK.

2. 앱 기동 (app.py 있는 본인 폴더에서)
   ```bash
   uvicorn app:app --port 8000
   ```
   그리고 백엔드 상태 확인:
   ```bash
   curl http://127.0.0.1:8000/health
   # "ollama":true 이면 게이트웨이까지 연결 정상
   ```

3. 대표 질문 1개 — 출처 태그가 먼저 뜨는지 보기
   ```
   활동성 폐결핵 격리해제 조건이 뭐야?
   ```
   기대: `IC-02 | 결핵관리지침` 같은 **출처 태그**가 먼저 뜨고, 혼잣말(`<think>` 등) 없이 깔끔한 근거 답이 흘러나옵니다. 지침에 없는 질문에는 "확인되지 않습니다"로 거절되면 성공.

---

### ⑤ 안전

- **환자 식별정보(PHI) 절대 입력 금지** — 환자명 · 등록번호 · 주민번호 · "병실+이름"은 넣지 마세요. 앱이 차단하더라도 **입력 자체를 안 하는 것이 원칙**입니다. 질문은 질병 · 지침 내용만 (예: "MRSA 격리 해제 기준").
- **더미 · 비식별 데이터만** — 실제 사례 · 내부 통계는 반드시 비식별 처리된 값으로만 다루세요.
- **거절 규칙 유지** — 검색된 지침 자료에 근거가 없으면 지어내지 말고 "확인되지 않습니다"로 답하도록 시스템 프롬프트를 지켜주세요.
- **공유 GPU는 하나** — 한 번에 한 질문씩. 테스트가 끝나면 `uvicorn`을 내려(Ctrl+C) 불필요한 부하를 남기지 마세요.
