## 08. 간호부 — 간호지원 · 공유 API 붙이기 프롬프트

> ⚠️ **대외비 과목입니다.** 이 앱은 원격 모델(:11500)을 호출하므로, 입력창·코드에 넣은 내용은 외부로 나갑니다. **반드시 더미(가짜 교육용) 자료로만** 진행하세요. 실제 임상정보·간호 프로토콜 전문은 절대 금지입니다.

---

### ① 한 줄 목표

내 간호지원 RAG 챗봇의 모델 호출을 **공유 게이트웨이(http://121.138.151.6:11500)** 로 바꾸고, 게이트웨이가 대신 처리하는 코드는 정리하고, "자료에 없으면 확인되지 않습니다" 거절 규칙을 시스템 프롬프트에 확인·추가한다. 손으로 고치지 않고 **Claude Code에 아래 프롬프트를 붙여넣어** AI가 하게 시킨다.

---

### ② 복붙 프롬프트 (Claude Code에 이걸 그대로 붙여넣으세요)

```
너는 내 간호지원 RAG 챗봇(A형 근거기반 챗봇)의 코드를 고치는 조수야.
내 앱은 [프론트 index.html] → [내 백엔드 app.py(:8000)] → [모델 서버] 3층 구조이고,
백엔드만 모델 서버를 호출해. 아래 작업을 순서대로 하되, 확실치 않으면 먼저 물어봐.

1) 모델 주소를 공유 게이트웨이로 통일
- 본인 앱 백엔드에서 모델 서버 주소가 적힌 줄(예: OLLAMA_URL 같은 변수, 또는
  주소가 직접 박힌 곳)을 전부 찾아줘. 특히 :11434 나 :11500 이 들어간 줄.
- 그 주소를 모두 http://121.138.151.6:11500 로 바꿔줘.
- 가능하면 주소를 파일 상단 변수 한 곳(예: OLLAMA_URL)에 두고, 임베딩 호출
  (/api/embeddings, bge-m3:latest), 생존확인(/api/tags), 채팅 호출
  (/api/chat, qwen3.6:35b-a3b) 세 군데가 전부 그 변수를 쓰게 정리해줘.
- 프론트(index.html)에서 :11500 이나 ollama 를 직접 부르는 코드가 있으면
  그건 보안 위반이야. 지우고 반드시 내 백엔드(:8000)만 부르게 바꿔줘.

2) 게이트웨이가 대신 해주는 코드 정리
- 이제 게이트웨이가 think 제거·답 길이 상한·모델명 정규화를 자동으로 해줘.
  그래서 백엔드에서 아래 것들이 있으면 불필요하니 찾아서 정리(삭제 또는 주석)해줘:
  · 채팅 요청 본문에 "think": true/false 를 직접 넣던 부분
  · num_predict / max_tokens 같은 답 길이 상한을 직접 세팅하던 부분
  · 응답에서 <think> 태그나 모델 혼잣말을 잘라내려고 직접 후처리하던 코드
- 단, 이걸 지워서 동작이 깨지지 않는지 확인하고, 애매하면 지우기 전에 알려줘.

3) 거절 규칙 확인·추가 (안전 핵심)
- 백엔드의 시스템 프롬프트(모델에게 주는 지시문)를 찾아줘.
- 거기에 "제공된 근거 자료에 없는 내용은 지어내지 말고
  '자료에 없어 확인되지 않습니다'라고 답하라"는 규칙이 있는지 확인하고,
  없으면 추가해줘. 출처(근거 조각)를 함께 밝히도록도 지시해줘.
- 이 앱은 교육용 더미 자료만 쓰며, 실제 간호 적용은 부서 프로토콜 확인이
  필요하다는 안내 문구도 답변 성격에 맞게 시스템 프롬프트에 넣어줘.

4) 마무리
- 바꾼 파일과 바뀐 줄을 요약해서 알려줘.
- 하드코딩된 주소가 더 남아있지 않은지 다시 한 번 훑어줘.
- 실제 환자정보나 실제 프로토콜을 코드에 넣지 말라고 나에게 상기시켜줘.
```

---

### ③ 이 프롬프트가 실제로 바꾸는 것

- 모델 호출 주소를 전부 **:11500(공유 게이트웨이)** 로 통일하고, 한 변수로 모아 관리하게 만든다.
- `think` 세팅·`num_predict`(길이 상한)·`<think>` 후처리 등 **게이트웨이가 자동 처리하는 코드를 제거**해 백엔드가 단순해진다.
- 시스템 프롬프트에 **"자료에 없으면 확인되지 않습니다" 거절 규칙**과 출처 표기 지시를 확인·보강한다.
- 프론트가 모델 서버를 직접 부르는 보안 위반이 있으면 **백엔드(:8000)만 부르도록** 바로잡는다.

### ④ 붙인 뒤 확인

1. **게이트웨이 생존 확인**
   ```bash
   curl http://121.138.151.6:11500/health
   ```
   응답이 오면 정상. (모델 목록까지 보려면 `curl http://121.138.151.6:11500/api/tags` — 목록에 `qwen3.6:35b-a3b`·`bge-m3`가 보이면 좋음.)

2. **앱 기동**
   ```bash
   uvicorn app:app --port 8000
   curl http://127.0.0.1:8000/health
   ```
   `{"ok":true,"ollama":true}` 처럼 `ollama:true`면 내 백엔드 → 게이트웨이 연결 정상. 이어서 브라우저에서 `index.html`을 열어 채팅창 확인.

3. **대표 질문 1개 (더미 자료 기준)**
   ```
   수혈 검사 전후에 뭘 확인해야 해?
   ```
   기대: 답과 함께 **출처(예: "근거: 수혈")** 가 뜨고, `<think>` 태그나 모델 혼잣말 없이 깔끔한 답만 나온다. 혼잣말이 섞이면 주소가 `:11500`인지 다시 확인.

### ⑤ 안전수칙 (대외비 — 가장 중요)

- **실제 임상정보 절대 금지** — 환자명·등록번호·주민번호·병실+이름, 실제 간호 프로토콜 전문을 입력창·코드에 넣지 마세요. 넣은 내용은 원격 모델로 나갑니다.
- **더미(가짜)만 사용** — 3주차 가짜 8조각(EGD·대장내시경·수혈·조영CT·MRI·채혈·심전도·복부초음파)처럼 비식별 교육용 예시로만.
- **외부(상용) 모델 전송 금지** — ChatGPT·Claude 등 사내 게이트웨이 밖 모델에 간호 자료를 붙여넣지 마세요. 호출 대상은 **오직 http://121.138.151.6:11500** 뿐입니다.
- **거절 규칙 유지** — 근거에 없으면 "확인되지 않습니다"로 답하게 두고, 모델 답은 참고용. 실제 간호 적용은 부서 프로토콜·담당자 확인을 거치세요.
- **프론트는 백엔드만** — `index.html`에서 `:11500`·`ollama`를 직접 부르지 마세요. 테스트가 끝나면 띄운 `uvicorn`을 내려(Ctrl+C) 공유 GPU 부하를 남기지 마세요.
