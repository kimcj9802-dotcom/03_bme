# 식약처 API HTTP 500 디버깅 결과 (2026-07-01)

## 증상
수업 중 식약처 회수·판매중지 API 호출 실패. 원 코드 호출 →
`https://apis.data.go.kr/1471000/MdlpRtrv1S1eStpgeInfoService02/getItemNameList01`
→ **HTTP 500 "Unexpected errors"** (공공데이터포털 표준 에러가 아닌 게이트웨이 라우팅 실패 신호).

## 근본원인 (라이브 재현으로 확정)
**서비스 경로명 오타.** `MdlpRtrv1S1eStpgeInfoService02` 에서 `l`(엘)↔`1`(숫자1) 혼동:
- `Rtrv1` → `Rtrvl` (Retrieval/회수), `S1e` → `Sle` (Sale)
- 정확명: **`MdlpRtrvlSleStpgeInfoService02`** (Mdlp=의료기기, Rtrvl=회수, Sle=Sale, Stpge=판매중지)
- 데이터셋: data.go.kr **15056785 "식품의약품안전처_의료기기 회수·판매중지정보"**

**재현 증거:**
| 호출 | 결과 | 의미 |
|---|---|---|
| 원본 경로(`Rtrv1S1e`) | HTTP 500 Unexpected errors | 경로 미존재(가짜 경로·무키·잘못된키 전부 동일 500) |
| 정정 경로 + `getItemNameList01` | **HTTP 401 Unauthorized** | ✅ 경로 정상 → 이제 '키 인증' 단계 도달 |
| 정정 경로 + `getItemNameList`(01없이) | HTTP 404 API not found | 오퍼레이션은 `...01` 필수 |

## ⚠️ 남은 이슈 — 키 미승인 (사용자 조치 필요)
경로 정정 후 **HTTP 401 Unauthorized**. 현재 키(`eaad...8944`)는:
- raw 키·URL인코딩 키 모두 401 → **인코딩 문제 아님**
- 다른 1471000 서비스에서도 401 → **키가 이 API에 활용신청 미승인/미구독**

**해야 할 일 (data.go.kr):**
1. 로그인 → 마이페이지 → 데이터활용 → Open API → **활용신청 현황**에서 데이터셋 **15056785 "의료기기 회수·판매중지정보"** 신청·**승인** 여부 확인. 미신청이면 상세페이지에서 활용신청(개발계정 보통 즉시 자동승인).
2. 마이페이지의 **정확한 인증키** 사용 — URL 문자열에 직접 붙이면 **Encoding 키**, `requests(params=dict)`로 넘기면 **Decoding 키**(라이브러리가 1회 인코딩). 섞으면 이중인코딩(%25) 오류.
3. 신규 발급/신규 매핑은 반영에 수십 분~수 시간 걸릴 수 있음.

> 요약: **코드 버그(경로 오타)는 수정 완료.** 실제 데이터를 받으려면 **유효·승인된 serviceKey**만 넣으면 됩니다.
